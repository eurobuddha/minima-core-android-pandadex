## Scheduling and proof scope

The shared FillSettler path serves Activity and background service. It alternates aggregate recovery with market recovery through a persisted database turn, so repeated host recreation cannot always consume the aggregate turn first. No aggregate candidates means market work can proceed in the same pass. One process-wide aggregate gate prevents overlapping aggregate lookups, and duplicate replies cannot repeat repair. Each batch contains at most four receipts and eighty selected source IDs; it uses the existing DexHistory wallet-history pager and its twelve-page/inclusion budgets. Missing legs, wrong payout, incomplete time or different immutable identity leave the original receipt queued. A different mined TxPoW is accepted only for the same immutable transaction with a prior missing check and later full proof in the same process epoch.

The pending flag is maintained in the same transaction as accepted inclusion checks, using the transaction index. Regular batch selection uses `takerreceipt_review(needs_review,retry,spentcoin)` rather than comparing every archived receipt with every check on each pass. The saved host query plans show index use for selection and retry sequencing; they are not phone latency measurements.

## Limits

The new aggregate correction branch has actual SQLite failure/rollback and reopen coverage. The deliberate process kills retain the existing competing-spender correction and full taker-completion scopes; they are not separate aggregate-correction crash tests. The Android harness does not invoke MainActivity's private methods or execute real SDK/IPC, production manifest/lifecycle, stock Samsung, save-picker/provider, hardware power-loss or actual disk-exhaustion paths.

Nine new JVM tests cover full-source/payout admission, incomplete proof retention, bounded batches, duplicate callbacks, corrupt/index-mismatched evidence, concurrent hosts, asynchronous exceptions, storage failure, shared-settler scheduling across host recreation, and visible accounting exclusion. Total: **415 JVM tests**, no failures/errors/skips. Release lint: zero errors, 75 warnings.

Receipt payloads are now capped at 512 KiB so combined original/new correction evidence leaves room for metadata under the [Android 16 reference CursorWindow configuration](https://android.googlesource.com/platform/frameworks/base/%2B/android16-release/core/res/res/values/config.xml), which specifies 2048 KiB. This is a local storage bound, not the chain's TxPoW limit or a guarantee for every device configuration. Existing larger schema-10 evidence is retained; oversized new captures keep their pending receipts without truncation. Full export memory and long-term archive growth remain open.

This does not reconstruct already-lost legacy expectations, discover every taker/pool trade with no retained intent, correct conflicting economics without further reconciliation, or classify a different immutable competing transaction as this trade. Pruned history can prevent a fresh full match. Stock MinimaCore/device testing and the human-only live composite release gate remain open; no complete-security claim is made.
