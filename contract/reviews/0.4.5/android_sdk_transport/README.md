# Android SDK transport audit — build 10

Executed on a fresh disposable Android 16/API 36 arm64 emulator with isolated ADB server 5049, keys and userdata. Audit package `com.eurobuddha.pandadex.audit`, version 10. No user phone, existing AVD, wallet or Minima node was accessed. Every outgoing SDK broadcast is intercepted by the harness ContextWrapper; even the synthetic `txnpost id:audit` string never leaves it. No INTERNET permission or production Activity/service is present.

## Results

**43 Android assertions passed.** The harness adapts the base project's `app/src/androidTest/java/org/minimarex/minimaapi/ApiInputTest.java`. It exercises actual Android Intents, SharedPreferences, receiver registration, JSON parsing, a same-UID nonexported FileProvider, executors and callbacks against the current SDK source. Coverage includes malformed/missing/wrong authentication, exactly-once delivery, preserved real node rejection, transport failures without status, file-size limits, unavailable files, 100 duplicate replies, a stalled reader with a two-item queue and one physical worker, 128 unanswered requests, expiry, destruction, dispatch exceptions, existing pairing preservation, failed commit acknowledgment and incomplete pairing.

The first host collector incorrectly required an optional instrumentation output marker after the harness had returned `PASS 43 assertions`. The raw successful stream was preserved and the collector's acceptance condition corrected without rebuilding or rerunning the APK. Source hashes were checked before and after execution. This was a collector-format assertion failure, not a failing Android test.

The pairing failure test injects a false durability acknowledgment through a preferences proxy. It is not physical disk-exhaustion/power-loss testing. Deadline tests invoke the registered expiry Runnable directly; they establish callback/state semantics without waiting ten minutes or measuring Samsung scheduling. URI reads use an actual local FileProvider, not cross-package node grants. The duplicate flood is delivered through the real receiver/SDK methods, not an external hostile APK.

## Implementation and reuse

The five SDK classes are reused from `../base/minimaapi/src/main/java/org/minimarex/minimaapi/`. Messages, package target, command/file formats and existing pairing IDs remain compatible. The donor uses SecureRandom for new pairing/request IDs and checks malformed inputs. PandaDEX adapts its failure contract, bounds and lifecycle; the original AAR remains at `app/libs/minimaapi.aar` but is no longer compiled. Apache-2.0 license and modification attribution are included in production assets. Donor hashes are retained in `provenance.json`.

The old bundled AAR used java.util.Random, unbounded URI reads and a get/remove callback sequence. The newer source donor's read/parse failures used `status:false`, which would be unsafe for PandaDEX's write-quarantine contract. The adopted source uses `transporterror` without `status` or `enabled`; only a complete authenticated node reply can claim node status. JSON must be one complete object, not a partial object with trailing content. Streaming reads stop above 4 MiB; inline payloads are bounded by both characters and UTF-8 bytes.

Requests are claimed before URI work is queued. The SDK has one physical reader, two queued reads and at most 128 unanswered callbacks. Each callback expires after ten minutes with an unknown outcome. It never replays a request. This retains late transaction-ID replies beyond PandaDEX's three-minute outer write timeout; replies after retention need the existing recovery path. The private app-side bridge has corresponding callback/queue bounds, removes duplicate file responses, checks reply message type and same UID, and expires five seconds later. The outer funds marker remains untouched by any of these unknown-outcome errors.

Existing valid pairing IDs are retained and committed before registration. Partial/corrupt pairing does not silently generate a replacement, and a failed commit blocks dispatch. Future IDs use SecureRandom; this does not retroactively increase the entropy of IDs generated by an older install. AndroidX receiver registration preserves the app's API-28 minimum compatibility path; only API 36 was executed here.

## Reproduce and limits

Use `build_harness.py` with a fresh output directory and **audit version 11 or greater**. Select only an explicitly isolated disposable emulator and invoke `com.eurobuddha.pandadex.audit/org.minimarex.minimaapi.SDKAndroidAudit`. Require the raw `PASS 43 assertions` stream. Never invoke this against a user node. Production source remains 0.4.5/405; no production APK was built or overwritten and older audit APKs remain preserved.

**421 JVM tests pass, no failures/errors/skips; release lint has zero errors and 75 warnings.** Six new JVM tests cover reply/error semantics, exact byte boundaries, multi-byte text, malformed/trailing payloads and pairing format. The earlier database build-9 evidence remains at its recorded source checkpoint and was not rerun for this SDK-only change.

Stock MinimaCore/S23/ZFold interoperability, cross-process Binder behavior, cross-package URI grants, older Android runtime execution and Samsung background/process-death behavior remain open. A malicious or stuck provider can occupy the single physical reader; bounds prevent unbounded replacement workers/queues but do not prove interruption of all provider I/O. Android unmarshals a broadcast before SDK checks, so the private-process containment remains necessary. This does not establish production approval or complete security.
