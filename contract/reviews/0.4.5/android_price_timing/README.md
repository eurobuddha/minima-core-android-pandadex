## Fixes

- Oracle receipt age, fetch pacing and maker-cycle pacing now use Android `SystemClock.elapsedRealtime()`. This clock is independent of calendar-time adjustments and includes deep sleep. A price is stamped at request start, not response completion. The background service pass throttle, heartbeat alarm and task-removal wake-up also use elapsed time. A negative/uninitialized sentinel permits the first maker cycle at boot-time zero and prevents a backwards-clock anomaly from freezing withdrawal. Existing timestamps identifying historical transactions are unchanged. [Android SystemClock reference](https://developer.android.com/reference/android/os/SystemClock).
- Each HTTP depth read has a30-second acceptance deadline covering headers, body, close, parsing and final quote acceptance. Remaining time is passed to socket timeouts where supported. Trickle reads cannot repeatedly extend the budget. Responses still have the16KiB body cap, caches and redirects are disabled, and unsuccessful HTTP responses do not read an error body. Late or invalid responses preserve the old price's original age and cannot clear suspect-price quarantine. Java's read timeout is an individual blocking-read limit, not a whole-response deadline; the elapsed checks supply the latter acceptance rule. [URLConnection timeout contract](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/net/URLConnection.html#setReadTimeout(int)).
- A first suspect-jump sample now expires at the existing20-minute maximum quote age. This permits the normal15-minute background cadence to obtain a second reading while refusing corroboration by an expired sample. Each individual request must still complete within30seconds. The exact20-minute boundary rejects the older sample. Both readings still come from the same exchange.

## Reuse

`NodeTransportService.java` supplied existing Android elapsed-time use; `ExportChecks.java` and its tests supplied the injectable clock and elapsed-budget approach. `MarketPrice` retains its depth validation, jump/quarantine and widening rules. The original sibling minimaSwap/PandaPools price readers and minimaSwap heartbeat use calendar clocks/per-read timeouts, so directly copying them would retain the identified defect. `DexKeepAliveService` and `HeartbeatReceiver` retain their existing scheduling/relaunch paths with a matching elapsed clock and alarm type. No new scheduler library or oracle was introduced.

## Evidence and limits

JVM tests use injected elapsed clocks and controlled HttpURLConnection implementations: initial timestamps near boot rather than the epoch; ageing through sleep-sized intervals; clock anomalies; delayed accepted-result refusal; expired suspect samples; normal background cadence; slow headers/body/close; reduced remaining timeout; redirects/errors without reading their bodies; oversized and malformed responses; first-cycle-at-zero admission and exact one-minute pacing; and stale withdrawal when the prior throttle timestamp is ahead of the current clock. No actual clock on a user device was changed, and no external price endpoint was contacted.

The Android harness verifies the actual production oracle clock and public MakerEngine constructor against real `elapsedRealtime()`, checks quote age, schedules the actual HeartbeatReceiver alarm, and cancels its PendingIntent. It does not instantiate the production service or issue node commands. The audit package lacks exact-alarm permission, so this exercises the inexact fallback. Saved alarm evidence shows a requested15-minute alarm could be delivered as late as roughly26minutes after scheduling. Alarm delivery, Doze and stock Samsung behavior were not executed; the scheduling-type proof is not a prompt-withdrawal guarantee.

**Source checkpoint distinction:** after audit16, review found that its provisional60-second corroboration window was shorter than the normal background cadence. The final source uses the existing20-minute quote-age ceiling with strict expiry, and the added JVM regression passes. Those are the only production-source differences after the Android run. Audit16's exact MarketPrice source is retained in `audit16-MarketPrice.java.txt` and matches its recorded SHA256. Runtime clock/alarm paths are unchanged by that follow-up. The final source/test hashes are in `../validation.json`; no new APK was built for the constant/boundary adjustment.

An underlying DNS/native/provider operation can ignore or overrun a socket timeout. The one admitted price worker stays occupied until it returns; the code rejects a late result, but does not claim every native call terminates within30seconds. A timely local receipt does not prove the exchange's book was recently generated, honest, liquid or manipulation-resistant. Repeated reads are not independent oracle corroboration. Background scheduling can be delayed by Android, and already live orders cannot be withdrawn instantly or retroactively repriced. Stock S23/ZFold MinimaCore, actual system alarm delivery/background recovery and the human-only composite interoperability gate remain open. No production or100%-security approval is asserted.
