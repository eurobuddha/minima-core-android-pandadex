# Owner history access and evidence export

The completed-operation archive previously had no export and only a fixed newest-record list. It now uses bounded50-record cursor pages, keyed by original recorded time plus receipt ID; new arrivals do not shift older pages. Newest refreshes the cursor. An export action remains accessible even with no trades or a history read error.

Reused `OrdersTab.java` Operations cards and `Design.java` tokens in the extracted `OwnerHistoryView.java`; reused `DexDb.java` captureExport/read transaction, `TradeExportFiles.java` streaming private-file/ZIP protocol, and `MainActivity.exportTradeReconciliation`. The minimum adaptations are owner cursor queries, one additional streamed archive entry, view navigation and readable existing text colours. Original receipts remain immutable. All saved owner receipts are exported independently of the trade date window as `owner-receipts.json`, with exact original JSON strings plus separate last saved node-check metadata. Export is a local snapshot, not fresh owner verification. Owner records never become trade/P&L entries.

Five new JVM tests cover exact evidence/timestamp preservation, zero invented totals/fresh lookup, complete257-row export beyond a UI page, source failure cleanup, malformed/trailing/oversized input rejection and legacy snapshot compatibility.
