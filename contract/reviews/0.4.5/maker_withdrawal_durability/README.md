# Maker withdrawal intent and status — 2026-09-10

**462 JVM tests pass**, zero failures/errors/skips. Release lint: zero errors/75 warnings. Eight new durability/recovery regressions are included, alongside updated existing status assertions. No APK, emulator or user device was built/launched/accessed for this pass; no node commands or network requests were made. Source remains0.4.5/405 and frozen0.4.4 is unchanged. Audit16 is retained Android evidence at its own earlier checkpoint, not runtime coverage of these changes.

## Findings and fixes

**Crash gap before cancellation:** cancelAllLadder removed each live order's slot before persisting its cancellation tracking entry. A crash or missing callback could leave neither identity durably tracked by the maker. `MakerConfig.prepareWithdrawal()` now commits cancellation identities while original slots/prepared intents remain intact. Only an acknowledged commit permits slot removal and cancellation dispatch. If slot removal later fails to persist, the already committed withdrawal record still protects the identity. The batch callback retains the existing retry/pacing behavior.

**Interrupted intent unreachable from UI:** MainActivity's withdrawal early return tested only slots and cancellation records, even though the button offered to withdraw a prepared-only create. `hasRecordedOrders()` includes the prepared intent, and the Activity uses it before delegating to the existing MakerEngine recovery path. The engine durably records that order ID before clearing preparedCreate. An unreadable prepared intent is preserved and reported; it is not discarded as an empty ladder.

**Ignored persistence acknowledgement:** MakerConfig.save now reports commit failure and rejects partial serialization instead of continuing with incomplete JSON. A failed save latches a process-local maker storage failure. New maker quotes stop at the cycle/quote guards even if Android's in-memory preference values show the failed edit. Successful automatic bookkeeping does not clear this latch; an explicit Publish or Withdraw action must successfully save its settings. These UI actions report failed saves rather than claiming publication/withdrawal started. Already authorized cancellation remains independent of the external feed, with its own required durable intent.

**Unsupported status claims:** a stale price no longer labels the ladder WITHDRAWN; armed settings say MAKER ENABLED rather than PUBLISHED. Missing maker records do not claim nothing exists on-chain. An absent recorded rung is described as not seen in the current snapshot, without inferring mining or estimating its transaction time from block distance. Repricing and cancellation tracking no longer promise confirmation from elapsed time/absence. Withdrawal completion text does not claim every attempted batch was sent when some failed. The publish explanation now states that background checks are normally requested every15minutes, Android may delay/stop them, and existing orders remain tradeable until cancellation confirms.

## Reuse and tests

The fix reuses MakerConfig's current preference serializer/tombstone records and MakerEngine.withdrawAll's existing prepared-intent recovery, rather than adding a second tracking store. The SharedPreferences proxy seam follows `android_reader_lifecycle/SDKAndroidAudit.java`; its JVM adapter models separate visible/durable maps so a failed commit can change memory while leaving disk unchanged. It invokes the real MakerConfig serializer and loader. Eight cases cover lost cancel reply, failed pre-dispatch commit, failed later slot removal, prepared-only withdrawal, failed prepared-intent transition, corrupt prepared data, serialization failure, and failed settings visible in memory that cannot authorize quotes until explicit acknowledged recovery. Existing maker cancellation, asynchronous ownership and status tests also pass.

This is deterministic JVM boundary evidence. Actual process termination, device filesystem-full behavior, Activity clicks/layout and real node cancellation were not executed in this pass. Saved XML and current source/test hashes identify its scope.

## Remaining work

The storage-failure latch is **process-local**. A failed pause/save may leave older enabled settings on disk, and restarting can restore them; the UI warns about this. Durable recovery across that failure/restart boundary still needs work. Generic config editing callbacks still rely on the shared pause/status rather than all individually handling a boolean save result. Corrupt MakerConfig loading and complete cross-instance serialization remain review topics.

Cancellation tracking entries remain until proven terminal; historical matching/retirement is not implemented by this change. A book snapshot's absence alone does not prove cancellation. Other maker evidence problems remain: cached-book/ownership freshness and distinguishing a buy order's quantity reduction due to repricing from an actual partial fill. The latter can affect future maker decisions and requires separate correction, not just wording. Background pairing/wake-up lifecycle and stock S23/ZFold MinimaCore behavior are unverified. No production approval or100%-security claim is made.
